# 菜单模块：数据库与接口设计

## 一、模块边界

菜单模块负责导航树配置和当前用户导航投影。它不负责业务接口授权，也不决定页面内创建、修改、删除等动作。

菜单配置与前端页面注册通过稳定页面标识衔接：数据库决定是否展示、父子关系和排序，前端决定该页面标识如何渲染。

## 二、数据库设计

### 2.1 `menus`：菜单树

| 字段 | 类型 | 必填 | 设计说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 菜单主键 |
| `name` | 文本 | 是 | 默认展示名称 |
| `code` | 文本 | 是 | 稳定菜单编码 |
| `parent_id` | UUID | 否 | 父菜单；为空表示根节点 |
| `path` | 文本 | 是 | 前端导航路径 |
| `icon` | 文本 | 是 | 图标语义键，不保存任意脚本或样式 |
| `component_key` | 文本 | 否 | 前端页面注册标识；目录可为空 |
| `required_permission_id` | UUID | 否 | 页面显示所需读取权限 |
| `status` | 枚举 | 是 | `enabled` 或 `disabled` |
| `visible` | 布尔 | 是 | 是否参与导航展示 |
| `sort_order` | 整数 | 是 | 同级稳定排序，非负 |
| `sort_key` | 文本 | 否 | 兼容的人工排序键；不作为关系标识 |
| `i18n_key` | 文本 | 否 | 多语言文案键 |
| `created_at` | 时间 | 是 | 创建时间 |
| `updated_at` | 时间 | 是 | 更新时间及版本依据 |
| `deleted_at` | 时间 | 否 | 软删除时间 |

### 2.2 约束

- 有效菜单 `code` 和 `path` 大小写不敏感唯一。
- `path` 必须以 `/` 开头且长度不超过 300。
- 父菜单必须有效，不能等于自身，不能形成任意深度循环。
- 显示权限必须指向有效权限。
- 页面菜单必须有 `component_key` 和显示权限；纯目录可以没有。
- 有有效子菜单时禁止删除父菜单。
- `sort_order` 非负；同级同序号时以稳定编码作次级排序。

### 2.3 索引

- 父级与排序联合索引，用于构建树。
- 状态与可见性联合索引，用于导航筛选。
- 显示权限索引，用于按权限反查菜单。
- 有效路径和编码唯一索引。

## 三、页面标识与权限绑定

页面菜单的显示权限默认由 `componentKey` 对应的读取权限推导，例如用户页面绑定用户读取权限。这样可以避免管理员手工把用户页面绑定到不相关权限。

对于无法遵循“页面标识 + `.read`”的特殊页面，应通过受控映射配置，而不是允许请求直接提交任意权限标识。

目录菜单不直接绑定权限。只要任一有效后代页面命中用户权限，该目录就进入结果；没有可见后代的目录不展示。

## 四、菜单管理接口设计

| 方法与路径 | 权限 | 请求/查询 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `GET /api/menus` | `menus.read` | 名称、路径、状态、父级、分页排序 | 菜单分页列表 | 返回父级名称、显示权限摘要和版本 |
| `GET /api/menus/tree` | `menus.read` | 可选状态 | 完整管理树 | 用于父级选择和结构维护，不按当前用户页面权限裁剪 |
| `GET /api/menus/:id` | `menus.read` | 菜单标识 | 菜单详情 | 返回子级数量和引用摘要 |
| `POST /api/menus` | `menus.create` | 名称、编码、父级、路径、页面标识、显示配置 | 新菜单 | 自动推导显示权限并校验页面标识 |
| `PATCH /api/menus/:id` | `menus.update` | 可编辑字段、版本 | 更新后菜单 | 父级变更检查完整树环；页面变化重算权限 |
| `DELETE /api/menus/:id` | `menus.delete` | 菜单标识、版本 | 无内容 | 存在有效子菜单时拒绝 |

管理树与当前用户导航是不同用途：管理树用于配置，需要菜单读取权限；当前导航只返回用户实际可进入的页面及祖先目录。

## 五、当前用户导航接口设计

导航可以随会话一起返回，也可以独立读取：

| 方法与路径 | 认证 | 请求 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `GET /api/navigation` | 登录 | 无 | 当前用户菜单树和导航版本 | 按最新权限筛选叶子并补齐父目录 |

导航节点至少包含菜单标识、名称、编码、路径、图标、页面标识、排序和子节点。无需返回显示权限主键，避免前端重新实现权限筛选。

当角色、权限或菜单变更时，导航版本变化。前端可以刷新导航，但不能因为缓存中仍有旧菜单就绕过服务端权限。

## 六、创建与更新规则

### 6.1 创建目录

- 页面标识为空；
- 显示权限为空；
- 可以包含路径用于展开状态或默认跳转，但不能把目录路径当作业务授权。

### 6.2 创建页面

- 页面标识必须存在于允许的页面注册目录；
- 自动解析对应读取权限；
- 路径唯一；
- 父级若存在必须是有效目录或允许承载子页面的节点。

### 6.3 名称与多语言

名称变化时，如果当前多语言键是自动生成或与旧名称绑定，应重新生成或清空并提示维护。自定义稳定多语言键可以保留，但需要明确由维护者确认语义仍一致。

## 七、并发与变更影响

- 更新和删除携带版本，防止多人同时拖拽或编辑覆盖。
- 父级、状态、可见性、页面标识和显示权限变化都应使导航缓存失效。
- 路径修改属于兼容性变更，需要评估收藏链接和前端路由跳转；必要时保留重定向配置。
- 页面标识下线前先禁用对应菜单，再移除前端页面能力。

## 八、主要错误

| 场景 | 建议错误码 |
| --- | --- |
| 页面标识无对应读取权限 | `MENU_PERMISSION_NOT_FOUND` |
| 页面标识未注册 | `MENU_COMPONENT_NOT_FOUND` |
| 父菜单不存在或已删除 | `MENU_PARENT_NOT_FOUND` |
| 菜单自引用或形成循环 | `MENU_HIERARCHY_INVALID` |
| 路径或编码冲突 | `MENU_CONFLICT` |
| 菜单仍有有效子级 | `MENU_HAS_CHILDREN` |
| 并发版本冲突 | `RESOURCE_VERSION_CONFLICT` |

## 九、验收标准

- 管理树和当前用户导航语义分离。
- 页面菜单自动绑定正确的读取权限，不能随意绑定无关权限。
- 有叶子权限时补齐完整祖先链，没有可见后代时不显示空目录。
- 修改菜单可见性不会改变对应业务接口的授权结果。
- 父级变更在任何层级都无法形成循环。
- 路径和编码保持唯一，删除父菜单前必须处理子级。
- 并发结构调整产生明确冲突，导航缓存可正确失效。

# 模块数据库与接口设计

## 一、文档用途

本目录把总体设计落实到模块级数据结构和对外接口契约。每份文档统一说明：

- 模块边界与数据所有权；
- 表、字段、关系、约束和索引；
- 接口路径、认证权限、输入输出和业务规则；
- 事务、幂等、并发、错误与验收要求。

文档描述稳定契约，不描述控制器、服务类、数据库函数等内部代码组织。接口可以在保持契约的前提下调整实现方式。

## 三、数据库通用约定

### 3.1 命名与主键

- 表和数据库字段使用小写下划线命名。
- 业务实体默认使用 UUID 主键，避免跨环境合并时依赖自增序列。
- 稳定业务编码使用 `code`，展示名称使用 `name`；关系使用主键，导入和配置迁移优先使用稳定编码。
- 时间统一保存为带时区时间；纯业务日期使用日期类型。

### 3.2 生命周期字段

- 可编辑实体包含创建时间和更新时间。
- 需要保留历史引用语义的实体使用软删除时间。
- 状态与软删除分离：禁用可恢复，软删除退出有效集合。
- 普通查询默认只返回未软删除数据；审计等证据数据不使用普通软删除。

### 3.3 约束与索引

- 唯一性、外键、枚举范围、非空和格式规则由数据库兜底。
- 大小写不敏感标识在规范化后建立唯一约束。
- 高频筛选、排序、外键反查和树结构字段建立索引。
- 软删除实体的业务唯一性需明确是“全生命周期唯一”还是“仅有效记录唯一”。

### 3.4 访问边界

- 业务表不允许浏览器身份直接访问。
- 服务端持有业务数据库和对象存储的高权限凭据，并承担最终授权责任。
- 需要整体替换或批量提交的操作在数据库事务中完成。

## 四、接口通用约定

### 4.1 路径与数据格式

- 接口统一位于 `/api` 下，路径使用复数资源名。
- 请求和响应字段使用小驼峰命名；数据库命名不直接泄漏到接口。
- 除明确公开的身份入口外，所有接口都要求有效访问令牌。
- 输入只接受契约声明字段，未知字段拒绝。

### 4.2 分页与排序

分页查询统一接受 `page`、`pageSize`、`sortKey` 和 `sortDirection`。默认第一页、每页 20 条；单页上限 100 条。模块只能接受白名单排序字段。

分页响应统一为：

| 字段 | 含义 |
| --- | --- |
| `items` | 当前页数据 |
| `total` | 满足条件的总数 |
| `page` | 当前页码 |
| `pageSize` | 当前每页数量 |

### 4.3 错误

错误响应包含稳定错误码和可选字段级信息。至少区分：

- `401`：未认证、令牌失效或用户不可用；
- `403`：动作权限不足或目标资源受保护；
- `404`：目标资源不存在；
- `409`：唯一冲突、版本冲突或状态冲突；
- `422`：输入格式正确但业务校验不通过；
- `500/503`：内部错误或外部依赖不可用。

数据库原始错误、内部路径和敏感凭据不得直接返回。

### 4.4 幂等与并发

- 已读、解绑、注销等重复提交应得到一致结果。
- 批量替换接口提交完整期望集合，不采用多个无序增删请求。
- 对可能被多人编辑的配置，更新请求应携带版本或上次更新时间；版本不匹配返回冲突，不静默覆盖。
- 创建身份、上传文件等跨系统操作应支持幂等键，便于安全重试。

## 五、接口权限命名

权限统一使用 `resource.action`：

- `read`：查看列表、详情和导出非敏感数据；
- `create`：创建资源；
- `update`：修改资源或状态；
- `delete`：删除资源；
- `manage`：无法合理拆分的配置集合管理；
- `import/upload/download/link/assign_roles/manage_auth`：需要独立评估风险的专门动作。

不能用菜单编码、页面路径或角色名称代替动作权限。

# 审计模块：数据库与接口设计

## 一、模块边界

审计模块保存已鉴权业务操作的不可变证据，支持安全追踪、问题定位和责任说明。它不替代应用日志、指标监控或身份服务安全日志。

客户端不能直接写审计记录，操作者、请求入口、结果和关联标识均由服务端可信上下文生成。

## 二、数据库设计

### 2.1 `audit_logs`：审计记录

| 字段 | 类型 | 必填 | 设计说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 审计记录主键 |
| `occurred_at` | 时间 | 是 | 操作发生时间，服务端生成 |
| `actor_user_id` | UUID | 否 | 操作者业务标识；不强制外键保留历史 |
| `actor_name` | 文本 | 是 | 操作当时姓名快照 |
| `actor_account` | 文本 | 是 | 操作当时账号快照 |
| `action` | 文本 | 是 | 稳定动作编码 |
| `resource_type` | 文本 | 是 | 稳定资源类型 |
| `resource_id` | 文本 | 否 | 资源标识，兼容非 UUID 资源 |
| `request_method` | 文本 | 是 | 请求动作类型 |
| `request_path` | 文本 | 是 | 规范化请求入口 |
| `request_id` | UUID | 是 | 业务、审计和日志关联标识 |
| `status` | 枚举 | 是 | `succeeded` 或 `failed` |
| `status_code` | 整数 | 是 | 对外结果状态 |
| `changes` | JSON | 是 | 脱敏后的请求、响应或错误摘要 |
| `ip_address` | 网络地址 | 否 | 合法来源地址 |
| `user_agent` | 文本 | 否 | 客户端信息，限制长度 |
| `error_code` | 文本 | 否 | 稳定业务错误码 |

### 2.2 约束与索引

- 数据库拒绝审计记录更新和删除。
- actor 名称、账号、动作和资源类型非空；动作和资源使用小写下划线格式。
- 状态码限制在有效协议范围，状态与错误码保持逻辑一致。
- 为发生时间倒序、操作者与时间、资源与时间、状态与时间建立索引。
- `changes` 仅在确有查询需求时建立结构化索引，避免过度放大存储。
- `request_id` 建议唯一或至少建立索引；同一请求需要多条审计时增加事件序号或允许复合唯一。

## 三、审计生成规则

默认审计所有已鉴权写操作，并允许为下载、登录开通、权限替换等高风险读取或命令显式增加审计。

审计坐标包含资源、动作和目标标识。批量操作使用批次标识作为目标，并在摘要中记录总数、成功数和失败数；不为数万条记录无上限展开正文。

成功记录包含脱敏请求和必要响应摘要；失败记录包含脱敏请求、稳定错误码和安全错误摘要。无论成功失败都使用同一个请求关联标识。

## 四、脱敏与限幅

- 密码、访问令牌、刷新令牌、密钥、认证头、Cookie 和签名 URL 始终替换为固定占位符。
- 文件二进制只记录大小、类型和校验摘要，不记录内容。
- 对象深度、字段数、数组长度和字符串长度设置上限。
- 对姓名、电话、邮箱等个人信息按审计目的最小化记录；没有排障价值的字段不进入 changes。
- 脱敏在写入前完成，不能依赖查询时隐藏。

## 五、查询接口设计

| 方法与路径 | 权限 | 查询 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `GET /api/audit-logs` | `audit_logs.read` | 操作者、资源类型、资源标识、动作、状态、错误码、起止时间、分页排序 | 审计分页列表 | 默认最新优先，限制最大时间范围 |
| `GET /api/audit-logs/:id` | `audit_logs.read` | 审计标识 | 完整脱敏详情 | 不返回数据库内部错误或敏感原文 |
| `GET /api/audit-logs/export` | `audit_logs.export` | 与查询相同的受限条件 | 异步导出任务或受控文件 | 独立高风险权限，记录导出审计 |

审计写入没有客户端接口。查询默认要求时间范围或限制最大跨度，防止无界扫描和大规模敏感数据导出。

## 六、可靠性与保留

- 审计写入失败不重放业务操作，也不把已成功业务伪装为失败。
- 审计失败必须产生高优先级服务日志和监控告警，并保留请求关联标识。
- 更高合规等级可采用事务内 outbox 或可靠消息，使业务提交与审计事件不丢失。
- 保留周期、归档位置和访问权限按证据要求独立配置；日常管理员不能删除。
- 归档后仍应保持校验能力，可使用分区、校验和或不可变存储增强防篡改证据。

## 七、主要错误

| 场景 | 建议错误码 |
| --- | --- |
| 时间范围过大 | `AUDIT_QUERY_RANGE_TOO_LARGE` |
| 查询条件无效 | `AUDIT_QUERY_INVALID` |
| 导出规模超限 | `AUDIT_EXPORT_TOO_LARGE` |
| 审计记录不存在 | `AUDIT_LOG_NOT_FOUND` |

审计持久化失败主要进入内部告警，不应直接覆盖原业务错误码。

## 八、验收标准

- 已鉴权写操作成功和失败均产生可关联审计。
- 客户端无法伪造 actor 或直接写、改、删审计。
- 密码、令牌、Cookie、签名地址和文件内容不会进入记录。
- 用户改名或删除后，历史记录仍保留当时 actor 快照。
- 查询和导出有权限、时间范围和规模限制，导出本身被审计。
- 审计写入失败可被及时告警并通过 request ID 定位缺口。

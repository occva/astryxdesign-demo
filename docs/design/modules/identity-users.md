# 身份与用户模块：数据库与接口设计

## 一、模块边界

身份模块负责登录凭据和会话，用户模块负责业务档案、状态、组织归属和登录开通关系。密码由外部身份服务保存，不进入业务数据库。

该模块不负责定义角色权限内容，只保存用户与角色的关系；授权规则见 [RBAC 模块](rbac.md)。

## 二、数据库设计

### 2.1 认证身份

认证身份由身份服务管理，业务数据库只保存不可逆的身份标识关联。身份 metadata 仅用于首次绑定，业务档案建立后不作为权威数据源。

### 2.2 `users`：业务用户

| 字段 | 类型 | 必填 | 设计说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 业务用户主键 |
| `auth_user_id` | UUID | 否 | 认证身份唯一关联；为空表示未开通 |
| `name` | 文本 | 是 | 展示姓名，去除首尾空格 |
| `account` | 文本 | 是 | 稳定业务账号，规范化为小写 |
| `email` | 文本 | 否 | 业务联系邮箱，不等同于认证邮箱 |
| `phone` | 文本 | 否 | 联系电话 |
| `avatar_url` | 文本 | 否 | 头像地址 |
| `gender` | 文本 | 否 | 展示值，不参与权限判断 |
| `status` | 枚举 | 是 | `normal` 或 `disabled` |
| `department_id` | UUID | 否 | 所属有效部门 |
| `department_name` | 文本 | 否 | 部门名称派生快照 |
| `employee_no` | 文本 | 否 | 员工编号 |
| `job_title` | 文本 | 否 | 职位 |
| `manager_name` | 文本 | 否 | 直属负责人展示信息 |
| `enterprise_wechat` | 文本 | 否 | 企业通信账号 |
| `emergency_contact` | 文本 | 否 | 紧急联系方式 |
| `office_location` | 文本 | 否 | 办公地点 |
| `joined_at` | 日期 | 否 | 入职日期 |
| `tags` | 文本数组 | 否 | 自由标签，默认为空集合 |
| `last_login_at` | 时间 | 否 | 最近成功登录时间 |
| `created_at` | 时间 | 是 | 创建时间 |
| `updated_at` | 时间 | 是 | 更新时间 |
| `deleted_at` | 时间 | 否 | 软删除时间 |

### 2.3 关系

- `auth_user_id` 与认证身份一对一。
- `department_id` 指向一个有效部门；部门删除后用户关系必须先迁移或清空。
- 用户通过 `user_roles` 拥有多个角色。
- 用户可被部门负责人、文件上传者、通知已读、审计 actor 等模块引用。

### 2.4 约束与索引

- `account` 大小写不敏感且全生命周期唯一，长度 3–100，只允许字母、数字、下划线和连字符，并以字母或数字开头。
- `auth_user_id` 唯一，防止一个认证身份绑定多个业务用户。
- 业务邮箱在非空时大小写不敏感唯一；长度不超过 254。
- 员工编号在有效用户中唯一。
- 姓名非空且不超过 100；电话及组织扩展字段设置合理长度上限。
- 为有效用户状态、部门、创建时间和标签检索建立索引。
- 用户仍作为有效部门负责人时禁止软删除。

## 三、身份接口设计

| 方法与路径 | 认证 | 请求 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `POST /api/auth/login` | 公开 | 账号、密码 | 会话与用户上下文 | 先校验业务状态，再校验凭据 |
| `POST /api/auth/register` | 公开 | 姓名、账号、可选邮箱、密码 | 会话与用户上下文 | 只能获得启用的最小权限角色 |
| `POST /api/auth/refresh` | 公开 | Refresh Token | 新会话与最新用户上下文 | 无效、撤销或过期令牌拒绝 |
| `GET /api/auth/session` | 登录 | 无 | 当前会话与最新用户上下文 | 重新确认用户状态与授权 |
| `POST /api/auth/logout` | 登录 | 无 | 无内容 | 全局撤销刷新能力，本地清理幂等 |
| `POST /api/auth/password` | 登录 | 新密码 | 无内容 | 仅修改当前身份密码 |
| `POST /api/auth/profile` | 登录 | 可自助维护的资料字段 | 更新后的会话上下文 | 不允许修改账号、状态、角色 |

### 3.1 会话响应

| 字段 | 说明 |
| --- | --- |
| `token` | 短期访问令牌 |
| `refreshToken` | 刷新令牌；恢复会话时可省略新值 |
| `expiresAt` | 访问令牌过期时间 |
| `user` | 用户档案、角色摘要、权限编码和可见菜单 |

密码永不出现在响应。会话恢复不轮换刷新令牌时，客户端保留原有值。

### 3.2 注册校验

- 姓名长度 2–100。
- 账号长度 3–100，符合账号格式并规范化为小写。
- 业务邮箱可选且格式有效。
- 密码满足身份服务和应用共同定义的最低强度；生产策略不应只依赖长度。
- 账号冲突、最小权限角色缺失和身份绑定失败分别返回可区分错误。

## 四、用户管理接口设计

| 方法与路径 | 权限 | 请求/查询 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `GET /api/users` | `users.read` | 姓名、手机号、状态、创建日期、分页排序 | 用户分页列表 | 默认排除软删除用户 |
| `GET /api/users/:id` | `users.read` | 用户标识 | 用户详情 | 返回角色摘要和登录开通状态，不返回身份凭据 |
| `POST /api/users` | `users.create` | 档案、可选部门与角色集合 | 新用户详情 | 含角色时额外校验角色分配权限 |
| `PATCH /api/users/:id` | `users.update` | 可编辑字段、版本 | 更新后详情 | 目标保护；角色变化独立授权 |
| `PUT /api/users/:id/roles` | `users.assign_roles` | 完整角色标识集合、版本 | 最终角色集合 | 原子替换并执行防越权校验 |
| `DELETE /api/users/:id` | `users.delete` | 用户标识、版本 | 无内容 | 禁止删除自己及仍被有效资源引用的用户 |
| `POST /api/users/:id/auth` | `users.manage_auth` | 初始密码、幂等键 | 登录开通状态 | 只允许未开通用户；失败时补偿身份 |
| `PATCH /api/users/:id/auth/password` | `users.manage_auth` | 新密码 | 重置结果 | 目标必须已开通且允许管理 |

将角色替换设计成独立接口，可以避免普通档案更新隐式携带高风险授权变化。兼容旧页面时可暂时接受单角色字段，但目标契约应以完整角色集合为准。

### 4.1 用户列表项

列表应包含用户主键、姓名、账号、联系方式摘要、状态、部门、角色摘要、登录开通状态、最近登录时间、创建时间和更新时间。不返回认证身份内部邮箱、Refresh Token 或任何密码信息。

### 4.2 用户详情

详情在列表字段之外补充组织资料、标签、完整角色集合和可编辑版本。权限编码不作为被管理用户详情的必要返回；需要权限解释时通过专门的授权诊断视图提供。

## 五、事务与并发

- 创建用户与初始角色应在一个事务中完成；如果跨边界拆分，角色失败时回收尚未被引用的新用户。
- 用户档案更新与角色替换分开提交，避免普通字段成功而授权变化失败时语义不清。
- 角色集合替换使用版本校验和单事务。
- 登录开通使用幂等键；重复请求返回已完成结果或明确冲突。
- 用户禁用完成后，后续会话校验立即拒绝该用户。

## 六、主要错误

| 场景 | 建议错误码 |
| --- | --- |
| 账号不存在或凭据不匹配 | `AUTH_INVALID_CREDENTIALS` |
| 用户被禁用 | `AUTH_ACCOUNT_DISABLED` |
| 尚未开通登录 | `AUTH_ACCOUNT_NOT_PROVISIONED` |
| 账号或身份已存在 | `AUTH_ACCOUNT_EXISTS` |
| 身份已开通 | `AUTH_ACCOUNT_ALREADY_PROVISIONED` |
| 已开通账号试图改名 | `PROVISIONED_ACCOUNT_IMMUTABLE` |
| 删除自己 | `SELF_DELETE_DENIED` |
| 目标系统用户受保护 | `SYSTEM_USER_PROTECTED` |
| 角色分配权限不足 | `ROLE_ASSIGNMENT_DENIED` |
| 角色权限超出操作者范围 | `ROLE_PERMISSION_ESCALATION_DENIED` |
| 并发版本冲突 | `RESOURCE_VERSION_CONFLICT` |

## 七、验收标准

- 业务用户可以独立于认证身份创建和维护。
- 注册只能获得最小权限角色，不能提交自定义高权限角色。
- 用户禁用后现有会话下一次校验即失效。
- 用户档案更新不会隐式改变角色；角色替换原子且有并发保护。
- 登录开通重复请求不会创建多个身份。
- 身份绑定失败可以自动回收，且可用关联标识排查。
- 已开通账号不能被单边修改，密码和令牌不进入业务数据库。

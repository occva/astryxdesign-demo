# 文件模块：数据库与接口设计

## 一、模块边界

文件模块管理私有对象的业务元数据、临时下载和与业务资源字段的附件关系。对象存储保存二进制，业务数据库保存可查询、可审计的权威元数据和绑定关系。

原始文件名只用于展示。对象位置由服务端生成，客户端不能指定 bucket 或对象路径。

## 二、数据库设计

### 2.1 `files`：文件元数据

| 字段 | 类型 | 必填 | 设计说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 文件主键 |
| `bucket` | 文本 | 是 | 私有存储空间，服务端决定 |
| `object_path` | 文本 | 是 | bucket 内唯一、不可预测路径 |
| `original_name` | 文本 | 是 | 规范化后的原始名称 |
| `mime_type` | 文本 | 是 | 服务端识别或校验后的类型 |
| `size_bytes` | 长整数 | 是 | 文件字节数，非负 |
| `checksum_sha256` | 文本 | 建议必填 | 内容校验和，用于完整性与去重判断 |
| `status` | 枚举 | 是 | `ready/quarantined/failed/deleting` 等生命周期 |
| `uploaded_by` | UUID | 否 | 上传用户；删除用户后可置空 |
| `uploaded_by_name` | 文本 | 是 | 上传时姓名快照 |
| `metadata` | JSON | 是 | 受控扩展信息，默认为空对象 |
| `created_at` | 时间 | 是 | 上传创建时间 |
| `updated_at` | 时间 | 是 | 更新时间及版本依据 |
| `deleted_at` | 时间 | 否 | 元数据软删除时间 |

bucket 与对象路径组成唯一约束。为有效文件创建时间、上传者和状态建立索引。原始名称、MIME 和大小用于筛选，但不能作为唯一标识。

### 2.2 `file_links`：附件绑定

| 字段 | 类型 | 必填 | 设计说明 |
| --- | --- | --- | --- |
| `id` | UUID | 是 | 绑定主键 |
| `file_id` | UUID | 是 | 有效文件 |
| `resource_type` | 文本 | 是 | 业务资源类型 |
| `resource_id` | 文本 | 是 | 业务资源标识 |
| `field_key` | 文本 | 是 | 附件字段标识 |
| `sort_order` | 整数 | 是 | 同字段附件顺序，非负 |
| `created_by` | UUID | 否 | 绑定操作者 |
| `created_at` | 时间 | 是 | 绑定时间 |

同一文件、资源、字段组合唯一。为资源坐标与排序、文件反查建立索引。资源类型和字段键采用受限格式；高安全资源还应校验目标存在及操作者访问范围。

## 三、对象存储设计

- 使用私有 bucket，单文件默认上限 20 MiB；按业务风险配置允许类型。
- 对象路径由日期、上传者稳定标识、随机标识和安全扩展名组成。
- 不根据原始文件名生成路径，不允许覆盖上传。
- 下载使用短时签名地址，默认 60 秒；签名地址视为敏感信息。
- `quarantined`、`failed` 或 `deleting` 状态不能生成下载地址。

## 四、接口设计

| 方法与路径 | 权限 | 请求/查询 | 响应 | 核心规则 |
| --- | --- | --- | --- | --- |
| `GET /api/files` | `files.read` | 文件名、类型、状态、上传者、日期、分页排序 | 文件分页列表及绑定摘要 | 不返回 bucket 凭据和永久地址 |
| `GET /api/files/:id` | `files.read` | 文件标识 | 元数据和绑定详情 | 只返回有权查看的绑定信息 |
| `POST /api/files` | `files.upload` | 单文件、幂等键 | 文件元数据 | 校验大小类型，服务端生成路径 |
| `POST /api/files/:id/download` | `files.download` | 文件标识 | 短时 URL、过期秒数、下载名称 | 文件必须为 ready，并记录下载审计 |
| `DELETE /api/files/:id` | `files.delete` | 文件标识、版本 | 删除状态 | 按绑定策略拒绝或清理，支持幂等重试 |
| `POST /api/files/:id/links` | `files.link` | 资源类型、资源标识、字段键、排序 | 新绑定 | 校验文件、目标资源和访问范围 |
| `DELETE /api/files/:id/links/:linkId` | `files.link` | 文件及绑定标识 | 无内容 | 绑定必须属于该文件；重复解绑幂等 |

## 五、上传事务与补偿

上传顺序：校验输入、生成路径和校验和、写入私有对象、保存元数据。元数据写入失败时删除已上传对象；补偿失败时记录孤儿对象并告警。

幂等键绑定操作者与文件摘要。相同键重试返回同一结果；相同键但内容不同返回冲突。不能只按文件名去重。

如启用病毒扫描，上传完成后先进入隔离状态，扫描通过才变为 ready；失败或超时保持不可下载，并提供受控重试或删除。

## 六、删除状态机

建议删除使用状态机，避免对象与元数据跨系统中途失败：

1. 校验删除权限、资源引用和版本。
2. 标记为 deleting，立即禁止新下载和新绑定。
3. 按策略清理绑定并删除对象。
4. 完成元数据软删除。
5. 中途失败保持 deleting，后台可幂等重试并告警。

若业务要求附件在被引用时不可删除，应返回引用冲突；若允许级联解绑，必须在审计中记录受影响资源。

## 七、访问控制与隐私

- 查看元数据、下载内容、删除文件和绑定附件分别授权。
- 文件绑定到敏感资源后，下载除 `files.download` 外还要校验目标资源的读取范围。
- 签名 URL 不写入审计正文或普通日志。
- MIME 不能只信任客户端声明；高风险类型应检查文件签名并强制安全下载响应。
- 原始文件名规范化并限制长度，下载时防止响应头注入。

## 八、主要错误

| 场景 | 建议错误码 |
| --- | --- |
| 未提供文件 | `FILE_REQUIRED` |
| 超过大小上限 | `FILE_TOO_LARGE` |
| 类型不允许 | `FILE_TYPE_NOT_ALLOWED` |
| 文件未就绪 | `FILE_NOT_READY` |
| 仍被业务资源引用 | `FILE_IN_USE` |
| 目标资源无效或无权访问 | `FILE_LINK_TARGET_INVALID` |
| 幂等键内容冲突 | `IDEMPOTENCY_CONFLICT` |
| 对象存储不可用 | `FILE_STORAGE_UNAVAILABLE` |

## 九、对账与验收

后台对账定期识别：有元数据无对象、有对象无元数据、长期 deleting、绑定指向删除文件、校验和不一致。修复动作必须可审计。

- 对象路径不可由客户端控制，bucket 始终私有。
- 上传失败能补偿或进入可识别的孤儿队列。
- 只有 ready 文件可以获得短时下载地址。
- 下载同时满足文件权限和目标资源范围。
- 删除中断可幂等恢复，不出现元数据仍显示可用但对象已永久缺失。
- 绑定与解绑校验文件归属，重复请求结果一致。
